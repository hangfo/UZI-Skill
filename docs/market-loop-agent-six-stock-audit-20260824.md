## 为什么最后全部证据不足

1. **检索预算与证据门槛不匹配。** TFPM 只有 1 个独立来源，门禁仍要求另外 3 项；
   同一证据集上做两轮改写不会增加事实。
2. **源是二级分析，不是原始事件。** TFPM/MAIN/LLY 的候选很可能来自观点文章，文章
   自身不是公司公告、监管披露或官方经营数据，独立验证的起点先天较弱。
3. **实体解析发生在研究前但不够严格。** `CC` 出现跨资产同代码碰撞；`300024`
   把产品主题词映射为另一家公司。后续检索即使成功，也可能在研究错误实体。
4. **3B 同时承担摘要和映射查询生成。** 小模型可以压缩文本，但不应拥有最终证券实体
   决定权；最终映射应由带资产类型、交易所、CIK/ISIN/统一证券 ID 的确定性主数据完成。
5. **周日文章与交易日状态脱节。** 股票尚无新的成交确认，系统只能验证叙事，不能验证
   价格接受度、成交量或下一交易日反应。
6. **失败重试没有改变策略。** 两轮都显示缺失 3 项，说明 retry 没有切换查询、来源或
   升级到官方资料，只重写报告。

## 两套流程的取长补短

| 环节 | 同事 Market Loop | 最新 UZI | 合并后的最小正确做法 |
|---|---|---|---|
| 发现 | 10 分钟、跨市场、事件优先，速度强 | ticker-first，持续发现弱 | 保留 loop 作 discovery，UZI 作 research/risk gate |
| 摘要 | 3B 快速，成本低 | 规则+多维 fetcher | 3B 只输出结构化事件，不做最终证券绑定 |
| 实体 | provider registry 有候选但发生 CC/300024 污染 | 美股 issuer alias 已 fail-closed；ticker 输入仍默认信任 | 主数据键必须含 asset class、交易所、法人 ID；关系类型分 issuer/theme/counterparty |
| 证据 | 1 源后让 7B 反复改写 | 20 维覆盖、缺口显式，但事件仍可能漏最新文章 | 先取发行人官方/监管，再取至少 2 个独立来源；retry 必须换查询/来源 |
| 决策 | evidence-gate 严格，但 `0` 混淆不可评分与看空 | 综合分与投资分分离，仍有 diagnostics 定义不透明 | 三态输出：可评分 / 证据不足 / 实体失败；只有可评分才进入档位 |

## 推荐的 Agent 流程

1. **事件摄取**：保留 10 分钟轮询，记录 source event id、原始时间、抓取时间、时区、
   文本哈希和是否为观点文章。
2. **确定性实体门禁**：主键采用 `asset_class + venue + canonical_id`；同代码跨资产直接
   拒绝。主题词只产生 `theme_exposure`，不能升级为 `issuer_event`。
3. **证据包**：至少含一条发行人/监管主源、两条互相独立的外部来源、最新完整行情与
   财务 as-of；达不到时停止，不启动 7B 长报告。
4. **分层研究**：3B 负责分类与查询草案；规则主数据负责实体；7B 只基于结构化证据包
   写研究；UZI 负责多维评分与风险门禁。
5. **有信息增量的重试**：每轮必须记录新增来源数、覆盖 claim 数和变化的 query；无新增
   信息时立即终止，禁止同证据改写两次。
6. **点时绩效账本**：冻结候选时间、第一可交易价格、1/5/21/63 日总收益和相对基准收益，
   同时保留未通过实体/证据门禁的反事实样本，避免只看幸存者。
7. **监控指标**：实体精度、跨发行人污染率、证据门禁通过率、每轮新增证据、新闻到任务
   延迟、可交易信号率、净收益和最大回撤；不得用“生成了多少报告”替代投资效果。
